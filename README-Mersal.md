# مرسال | Mersal 📩

## نبذة عن المشروع

**مرسال** منصة ذكية تهدف إلى تحسين عملية تسليم المهام والمعلومات بين الموظفين **(Handover)** باستخدام الذكاء الاصطناعي.

يساعد النظام على جمع معلومات التسليم في نموذج موحد، ثم تحليلها وتنظيمها لإظهار المهام المعلقة، المواعيد القادمة، المخاطر، المسؤولين، العناصر الحرجة، الخطوات التالية، والمعلومات الناقصة؛ مما يساهم في تقليل الوقت والأسئلة المتكررة ورفع جودة عملية التسليم.

## الهدف من المشروع

- تحسين عملية تسليم المهام بين الموظفين.
- تقليل الوقت المستغرق في الـ Handover.
- تقليل فقدان وتشتت المعلومات.
- تقليل الأسئلة المتكررة بين الموظفين.
- توضيح المهام والمسؤوليات والأولويات.
- رفع جودة وكفاءة عملية التسليم.
- تحسين الإنتاجية واستمرارية العمل.

## الوضع الحالي | AS-IS

في عملية التسليم التقليدية قد يتم تسجيل المعلومات بشكل يدوي وغير موحد، مما قد يؤدي إلى:

- تشتت المعلومات.
- نقص التفاصيل المهمة.
- كثرة الأسئلة المتكررة.
- صعوبة معرفة الأولويات.
- استهلاك وقت أطول لفهم المهام.

## التقنيات والأدوات المستخدمة

- **React** — بناء واجهة المستخدم.
- **TypeScript** — تطوير المشروع مع دعم أنواع البيانات.
- **Vite** — تشغيل وبناء الواجهة الأمامية.
- **Tailwind CSS** — تصميم وتنسيق الواجهة.
- **Express.js** — بناء الخادم وواجهات API.
- **Google Gemini API** — تحليل وتنظيم معلومات الـ Handover.
- **Zod** — التحقق من صحة البيانات.
- **TanStack React Query** — إدارة طلبات الـ API.
- **Wouter** — التنقل بين صفحات الواجهة.
- **pnpm** — إدارة الحزم وبيئة الـ Workspace.
- **Replit** — تطوير وتشغيل واستضافة المشروع.
- **GitHub** — إدارة وحفظ الكود المصدري.

## أهم الملفات البرمجية

- `artifacts/mersal/src/App.tsx` — المنطق الرئيسي وواجهة منصة مرسال.
- `artifacts/api-server/src/routes/handover.ts` — تحليل بيانات الـ Handover والتكامل مع Google Gemini.
- `lib/api-zod/src/index.ts` — مخططات التحقق من بيانات الطلب والاستجابة.
- `lib/api-client-react/src/index.ts` — عميل API المستخدم في واجهة React.
- `lib/api-spec/openapi.yaml` — تعريف واجهات API.

## آلية عمل النظام

1. يدخل المستخدم معلومات عملية التسليم.
2. تتحقق الواجهة والخادم من صحة البيانات.
3. يتم إرسال البيانات إلى نقطة النهاية الخاصة بتحليل الـ Handover.
4. إذا كان `GEMINI_API_KEY` متوفرًا، يتم إرسال البيانات إلى Google Gemini للتحليل.
5. يعيد Gemini النتيجة في صيغة JSON منظمة.
6. إذا لم تتوفر خدمة Gemini، يستخدم النظام Demo Mode لإنشاء تحليل محلي.
7. تعرض النتيجة للمستخدم في صورة Brief منظم يتضمن المهام والمخاطر والمسؤولين والخطوات التالية وتقييم الجودة.

## تشغيل المشروع

### المتطلبات

- Node.js
- pnpm

### 1. تثبيت الحزم

```bash
pnpm install
```

### 2. تشغيل الخادم

```bash
pnpm --filter @workspace/api-server run dev
```

### 3. تشغيل الواجهة الأمامية

في Terminal آخر:

```bash
pnpm --filter @workspace/mersal run dev
```

### 4. فحص TypeScript

```bash
pnpm run typecheck
```

### 5. إنشاء نسخة الإنتاج

```bash
pnpm run build
```

## متغيرات البيئة

لاستخدام Google Gemini أضف مفتاح API إلى متغيرات البيئة:

```env
GEMINI_API_KEY=YOUR_GEMINI_API_KEY
```

> لا تقم برفع مفتاح API الحقيقي إلى GitHub.
